# 固定步数位置延迟下的跟踪采集任务

无人机从起点出发，跟踪非合作车辆尽量多采集，并在 100 步内到达终点。
至少采够 5 个完整接触步才算完成；失败（超时或已来不及返程）时本局采集作废。

车辆位置由外部监视系统提供；从探测到无人机收到，经过处理与转发共 d 步。
第 t 步只收到第 t−d 步的车辆位置；首次报告在第 d 步到达（内容是第 0 步的位置），此前不知道车在哪，
规则原地悬停。每步按 1 s 理解：车速 5 m/s、UAV 最大 8 m/s、
采集半径 10 m、地图 245 m；车辆全程 100 步都在行驶。d 为敏感性参数，不对应实测设备。
采集按车辆真实位置计算，但决策只用收到的位置。

## 设定

**车辆**：每步 5 m，只沿东南西北行驶。基础转向概率：直行 0.85、左右各 0.07、掉头 0.01；
方向权重再乘以 exp(1.0 × 本步缩短的到目的地曼哈顿距离/5)，到达后换新目的地，遇边界换方向。
目的地不告诉无人机。

**返程自动完成**：终点已知、返程是直线，所需步数可以精确算出；规则的离开余量在 0–10 步中搜索时
2 步最好。因此采够 5 后，时间余量降到 2 步时自动直线飞回终点，所有策略相同。

**观测（13 维）**：UAV 位置2、相对终点2、剩余步数1、最少采集进度1（累计/5，封顶 1）、
收到的车辆相对位置2（÷50 m；超出 50 m 时为单位方向）、车辆上一步位移2（÷5 m，即 ±1）、
时间余量1（剩余步数 − 直飞到终点所需步数，÷100）、是否已返程1、是否已收到报告1。
首次报告前车辆位置与位移填 0。残差控制时再加规则动作2，共 15 维。
不提供车辆真实位置、方向、目的地或未来路线。

**奖励**：每个完整接触步 +0.2（不封顶）；采够 5 之前，本步离车辆真实位置缩短的距离 ÷ 346 m；
到达终点 +2；失败 −2 并扣回整局采集分。得分 = 成功时的累计采集量，失败记 0。

## 三种策略

| 策略 | 说明 |
| --- | --- |
| 规则（线性外推） | 飞向 收到位置 + (d+1)×位移。观测无噪声时，等价于匀速模型下的卡尔曼预测 |
| 纯 PPO | 动作二维，从零学习 |
| 规则 + PPO 修正（残差） | 动作 = 规则动作 + 1.0 × PPO 修正量；初始修正较小（log_std_init=−1） |

三者信息、约束、奖励相同；残差与规则的唯一区别是有没有学习到的修正。

PPO 为 `train.py` 中的单文件 PyTorch 实现（不依赖 RL 库），超参数取常用默认值：
4 个并行环境 × 256 步、小批 64、每轮更新 10 遍、学习率 3×10⁻⁴、γ=0.99、GAE λ=0.95、裁剪 0.2、
价值损失系数 0.5、熵系数 0、梯度裁剪 0.5；策略与价值网络各 2 层 64 单元 tanh，正交初始化。
每次训练 100 万步，训练种子 0/1/2。

## 主要结果（测试集 420000–420199，200 个场景，逐场景配对）

残差得分为每个场景上三个训练种子的平均。差值 = 残差 − 规则；置信区间为 10000 次场景 bootstrap；
p 为 Wilcoxon 符号秩检验（双侧）。

| d | 规则 | 规则 + PPO 修正 | 差值 [95% CI] | p | 场景 更好/更差/相同 | 各种子均值 |
| --- | --- | --- | --- | --- | --- | --- |
| 2 | 46.17 | 46.32 | +0.15 [−0.36, +0.65] | 0.013 | 126 / 74 / 0 | 45.9 · 47.1 · 46.0 |
| 4 | 26.20 | 26.94 | **+0.75 [+0.12, +1.37]** | 0.004 | 122 / 78 / 0 | 27.9 · 26.2 · 26.7 |
| 6 | 14.33 | 15.43 | **+1.10 [+0.42, +1.78]** | 5×10⁻⁴ | 120 / 78 / 2 | 14.1 · 16.6 · 15.6 |
| 8 | 7.28 | 10.46 | **+3.18 [+2.30, +4.05]** | 1×10⁻¹¹ | 140 / 47 / 13 | 9.7 · 10.2 · 11.5 |

d=2 时平均差值的区间包含 0，规则已接近最优。d=4、6、8 时残差显著更好（分别高约 3%、8%、44%），
按 4 次检验做 Bonferroni 校正（α=0.0125）后仍显著；延迟越大，提升越明显。
种子间仍有差异：d=6 的种子 0 与规则无差异（p=0.81），其余两个种子显著更好。

开发场景上的补充观察（d=6）：第一次贴上车的平均步数，规则为 27.5，残差三个种子为 29.4 / 20.7 / 20.2
（种子 0 没有提前，也正是测试集上与规则无差异的那个种子）；收到的车辆距离超过 40 m 时修正量最大。

## 代码结构

| 文件 | 内容 |
| --- | --- |
| `config.py` | 全部实验参数（场景尺度、车辆运动、任务规则、观测、奖励） |
| `scenario.py` | 场景生成：起点、终点、车辆起点和整局车辆路线 |
| `contact.py` | 一步内的采集接触时长 |
| `rules.py` | 规则策略：只追收到位置、线性外推（残差控制也用它） |
| `env.py` | Gymnasium 环境：延迟观测、自动返程、判定、奖励、残差控制 |
| `evaluation.py` | 场景种子划分、读取训练配置、统一评估 |
| `train.py` | 入口：PPO 训练与复评 |
| `baselines.py` | 入口：规则基线评估 |
| `compare.py` | 入口：测试集逐场景配对比较与显著性检验 |
| `plots.py` | 入口：论文用结果图 |

依赖方向：`config` ← `scenario` / `contact` / `rules` ← `env` ← `evaluation` ← 各入口脚本。

## 运行

```powershell
python -m pytest tests -q
python -m uav_delay.baselines                  # 规则基线，结果在 outputs/delay_check/
python -m uav_delay.train --delay 6 --seed 0 --residual 1.0 --output outputs/delay_torch_resid_d6_seed0
python -m uav_delay.compare --split test       # 配对比较，结果在 outputs/delay_compare/
python -m uav_delay.plots                      # 结果图，输出到 outputs/figures/
```

测试 420000–420199（只用于上面的最终比较）。

## 开发过程中的结论

1. 返程交给策略学习时，PPO 要么不返程，要么离开过早；离开时机有精确解，因此改为自动返程。
2. 规则损失的分解（开发场景，开局已知车辆位置的早期设定）：约 45% 来自车辆刚转弯而信息未到（不可避免），40–50% 来自接近和
   转弯后追赶（可改进），边界转弯 1–6%。
3. 纯 PPO（从零学习）在开发场景达到规则的 97%（d=4）和 60%（d=6），未超过规则。
4. 用最近 2/4/8 步的平均位移外推（早期设定），比只用最近 1 步更差，因此不加入更长的历史或远期预测器。
