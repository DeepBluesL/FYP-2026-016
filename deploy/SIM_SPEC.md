# 仿真场景说明（与训练环境对齐）

接入分两步：

1. **完全对齐**：按下面的设定回放 `routes/test_routes.json` 里的车辆轨迹，结果应接近参考结果
   （理想网格下逐条相同）。这一步证明接入没有问题。
2. **逐步加入真实因素**：真实飞行动力学、可变延迟、道路网等，每次只改一项，观察性能变化。

## 1. 必须对齐的设定

| 项目 | 设定 |
| --- | --- |
| 场地 | 250 m × 250 m，无障碍；按 5 m 一格分成 50 × 50 格，格子坐标 0–49 |
| 坐标 | +x 向东，+y 向北；格子 (i, j) 对应相对无人机起点的 (东 5i m，北 5j m) |
| 时间 | 每 1 s 决策一次；一回合最多 150 s |
| 无人机起点 / 终点 | (0, 0) / (49, 49)，即 (0 m, 0 m) / (东 245 m, 北 245 m)，固定 |
| 无人机动作 | 17 个：悬停；8 个方向各走 1 格或 2 格（见 `README.md`） |
| 车速 | 每秒 1 格（5 m/s），每一秒都在动，不停车 |
| 车的走法 | 只走东南西北 4 个方向；直行 0.65、左右转各 0.15、掉头 0.05，再按“是否靠近目的地”加权（`uav_demo/vehicle.py`） |
| 车的起点 | 离无人机起点直线距离 8–15 格（40–75 m） |
| 车的目的地 | 离当前位置至少 20 格（横向 + 纵向）；到达后立刻换一个新目的地 |
| 延迟 | 第 t 秒收到车在第 t − d 秒的位置；d 固定为 4、6 或 8 s，与所用模型一致；第 d 秒之前没有报告 |
| 采集 | 每秒判定一次：无人机与车的直线距离 ≤ 10 m 记一次接触；连续 5 次完成，中断清零 |
| 返程 | 采完后沿最短路线飞回终点（`policy.act` 自动给出返程动作） |
| 成功 / 失败 | 采完并回到终点为成功；150 s 内没做到为失败 |

## 2. 容易漏掉的细节

1. **斜飞更快**：斜向一步走 (1, 1) 格，即 5√2 ≈ 7.1 m；“1 档”斜飞约 7.1 m/s，“2 档”约 14.1 m/s。
   用速度指令时直接按 `(格数 × 5 m) / 1 s` 给东、北两个分量即可。
2. **悬停保留速度档**：悬停时位置不变，但速度档保持上一步的值。`policy.next_state()` 返回的速度档已经按这个规则算好。
3. **报告时刻**：`builder.report(t, 位置)` 里的 t 是“这个位置对应的时刻”，不是报告到达的时刻。
4. **采集只在每秒的决策时刻判定一次**，用车的真实位置；两次决策之间不判定。
5. **只能把延迟报告传给策略**，不能传车的真实位置；真实位置只用于采集判定。

## 3. 回放测试路线

`routes/test_routes.json`（由 `export_routes.py` 生成）包含：

- `routes`：200 条测试路线，每条是车在 t = 0…150 每一秒的格子坐标；
- `reference`：在这些路线上的参考结果，按延迟 4 / 6 / 8 分别给出 deploy 模型（`cv_prediction_plus_rl`）
  和 CV prediction 的每条路线结果（是否成功、用时、何时采完）。

| 延迟 | 模型 | 成功率 | 平均完成时间（失败记 150 s） |
| --- | --- | --- | --- |
| 4 | d4.pt | 100% | 39.7 s |
| 6 | d6.pt | 99.0% | 46.5 s |
| 8 | d8.pt | 96.5% | 53.4 s |

## 4. Project AirSim 接入

`projectairsim_example.py` 已实现完整主循环：读取路线、生成延迟报告、调用策略、按速度飞 1 s、
用车的真实位置判定采集、判断成功。仿真平台只需要提供：

- 读取无人机真实位置（NED 的北、东分量）；
- `move_by_velocity_async(v_north, v_east, v_down=0, duration=1)`；
- 每回合开始时把无人机放回起点。

脚本里标 TODO 的三处（读位置、定高、每回合复位）需要按 Project AirSim 官方 API 文档核对后填写。

```bash
python deploy/projectairsim_example.py --backend grid --delay 6
```

先用 `grid` 后端运行，输出“routes with a different result: 0”说明主循环与训练环境一致；
再换成 `--backend projectairsim`。真实飞行有惯性，1 s 后不一定正好到达下一格，
结果比参考略差是正常的，差多少正是要测的内容。

## 5. 超出训练范围（需要重新训练或补测）

- 车的起点离无人机很远（如从地图对角出发）：模型不如 CV prediction；
- 车速不是 5 m/s、场地大小不同、有障碍物：未测试；
- 延迟每秒变化：未测试（固定延迟 2–10 s 之间换模型使用时表现良好）。
